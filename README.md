# findigo-web

Фронт маркетплейса. Nuxt с серверным рендером, ходит в `findigo-api`
по REST. Бэк про вёрстку не знает ничего.

## Запуск

```bash
npm install
cp .env.example .env
npm run dev
```

API по умолчанию ожидается на `http://localhost:8000/api`.

Проверки: `npm run check` — eslint, типы (vue-tsc) и сборка.

## Почему SSR, а не чистый SPA

Для маркетплейса органический поиск — основной канал привлечения,
а карточек сотни тысяч, и они постоянно появляются и исчезают.

- Яндекс исполняет JS в бете, по умолчанию «на усмотрение робота»,
  и в своей же документации рекомендует SSR или пререндеринг.
- Google рендерит, но с задержкой: страница попадает в индекс через
  недели, а краулинговый бюджет тратится на выполнение JS вместо обхода.
- Краулеры соцсетей, мессенджеров и ИИ-поисковиков JS не исполняют
  вовсе — ссылка на объявление уходила бы без превью.

При этом разделение сохраняется полностью: рендерит фронт, своим
рантаймом. Бэк остаётся чистым API и пригоден для мобильного приложения
и партнёров без единой правки.

## Устройство

```
app/
  composables/useApi.ts   единственная дверь в API
  composables/useI18n.ts  язык страницы и тексты: t('ad.price')
  pages/[lang]/           маршруты — всегда с языком: /ru/…, /en/…
  components/             компоненты
  types/api.d.ts          типы ответов — из OpenAPI бэка (npm run api:types)
shared/utils/languages.ts языки: проверка по ICU, Accept-Language, язык страны
server/middleware/        посетитель: страна и язык, визит раз за сессию
server/plugins/           регистрация en.json в бэке при старте
i18n/locales/*.json       тексты интерфейса в формате ICU
```

Компоненты не вызывают `$fetch` напрямую — только через `useApi()`.

## Языки

Язык — первый сегмент адреса, и доступен любой язык, который знает ICU:
списка в коде нет, `/xx` — 404, `/haw` — страница. Язык по умолчанию —
английский, `en.json` — исходный.

Тексты интерфейса, по старшинству:

1. `i18n/locales/{язык}.json` — переводы, которые правят люди. Готовит их
   команда бэка (правки людей она сохраняет, дописывает новые ключи):

   ```bash
   cd ../api && php artisan i18n:messages ../web/i18n/locales/en.json --to=ru --to=de
   ```

2. машинный перевод из бэка (`GET /api/i18n/web/{язык}`) — для языков без
   файла и для ключей, которых в файле ещё нет. Сервер фронта при старте
   регистрирует `en.json` в бэке; первый посетитель с новым языком
   заказывает перевод, бэк делает его очередью (`i18n:ui`);
3. `en.json` — пока перевода нет.

Корень сайта ведёт на язык посетителя, даже если интерфейса на нём ещё
нет: язык браузера (Accept-Language), иначе вероятный язык страны.

### Посетители

Сервер фронта определяет страну по IP: заголовок CDN (`NUXT_COUNTRY_HEADER`,
у Cloudflare — `CF-IPCountry`), иначе база MaxMind GeoLite2 Country
(`NUXT_GEOIP_DATABASE` — путь к `.mmdb`). Раз за сессию (cookie) он шлёт
бэку визит — страну и язык; бэк хранит только счётчик «день × страна ×
язык». IP дальше сервера фронта не уходит. Нужен `NUXT_INTERNAL_TOKEN` —
тот же секрет, что `INTERNAL_TOKEN` бэка; без него визиты не шлются.

`h3` 1.x стоит в devDependencies намеренно: `@nuxt/eslint` тянет h3 2.x
в корень `node_modules`, и типы Nitro начинают ссылаться на него.

Имена из справочников (категории, свойства, повреждения) переводит бэк:
`useApi()` передаёт язык страницы в каждый запрос на чтение.
